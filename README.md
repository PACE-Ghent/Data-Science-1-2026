# Data Science I — Dataverwerking I & II, Datavisualisatie I

Course materials for three linked 4.5-hour sessions built around one running story: students are the new data analyst for
a fictional youth football/athletics club, working with three exports from
the club's systems. 

## Folder structure

```
data/                  the three CSV files the whole course is built on
generate_data.py       script that generates data/ (synthetic, seeded)
requirements.txt       Python dependencies (marimo, pandas, plotly, numpy)
labs/                  student notebooks — hand these out
solutions/             instructor answer keys — same notebooks, fully solved
```

## The datasets (`data/`)

Generated by `generate_data.py` with a fixed random seed (`numpy` default
RNG, seed 42), so re-running it reproduces the exact same files.

| File | Contents | Rows |
|---|---|---|
| `athletes.csv` | One row per athlete: ID, name, birthdate, gender, position, height, weight | 43 |
| `tests.csv` | Physical test results (10 m / 30 m sprint, CMJ jump height, Yo-Yo level) across up to 3 test moments per athlete | ~110 |
| `hr_session.csv` | Heart rate + GPS speed, once per second, for 5 athletes during one 40-minute training | 12,000 |

The data is **deliberately messy**, on purpose, so the mess itself becomes
the teaching material in Session 1:

- inconsistent `position` labels (`"Forward"`, `"forward "`, `"FWD"`, ...)
- some sprint times stored in milliseconds instead of seconds (e.g. `5970`
  instead of `5.97`)
- missing values scattered across several columns
- one athlete duplicated under a second `athlete_id` (same name + birthdate)
- `weight_kg` stored as text with a comma decimal separator (`"57,5"`), like
  a European-locale spreadsheet export

To regenerate the data (e.g. after editing `generate_data.py`):

```bash
pip install numpy pandas
python generate_data.py
```

This overwrites the three CSVs in `data/`. Do this only if you intend to
change the dataset — the notebooks' exercise checks have specific expected
values baked in (row counts, position counts, etc.) that assume the current
seed. Changing the generator without re-checking the labs' assertions will
break the auto-checks.

## Running the notebooks

Install once:

```bash
pip install -r requirements.txt
```

Open a notebook for editing (either a student lab or an instructor
solution):

```bash
marimo edit labs/lab3_data_processing_I.py
```

This opens an interactive, reactive notebook in the browser. Cells re-run
automatically when their dependencies change.

To run a notebook read-only, as students would see a shared app:

```bash
marimo run labs/lab3_data_processing_I.py
```

## `labs/` — student notebooks

One "starter notebook" per session, matching the lesson plan's structure:
short intro, demo cells (fully worked, safe to run as-is), and exercises.

Every exercise cell contains a `...` placeholder:

```python
# TODO: select rows where position == "Forward" AND younger_than_16 is True
forwards_u16_raw = ...
```

The cell right below it checks the answer automatically and shows a
callout — green ("Correct!") or amber ("Not yet correct", with a hint)
— every time the notebook re-runs. Students replace `...` with their own
code; nothing else in the notebook needs to change.

| File | Session | Covers |
|---|---|---|
| `lab3_data_processing_I.py` | 3 - Dataverwerking I | load, explore, filter, new columns, cleaning |
| `lab4_data_processing_II.py` | 4 - Dataverwerking II | groupby/agg, merge, melt/pivot, time series (zones, rolling, resample) |
| `lab5_data_visualization_I.py` | 5 - Datavisualisatie I | chart selection, plotly express, color/facet/size, HR zone bands, marimo interactivity, mini-dashboard |

Two things are intentionally unusual and worth knowing before teaching from
these:

- **Lab 2 opens with a broken cell on purpose** (`## 1. Recap`): a tiny
  cleaning pipeline with two bugs (a typo, a missing comma→dot conversion)
  that students fix live as a warm-up repair exercise. Running the lab
  end-to-end as shipped will show exactly one real Python error there —
  that's expected, not a bug in the notebook.
- **Lab 3's "principles" section shows one good and one deliberately
  misleading chart** (a truncated y-axis), for students to critique before
  building their own charts.

## `solutions/` — instructor answer keys

Identical notebooks, with every `...` replaced by a correct, verified
solution (and Lab 2's recap bug already fixed). Use these to:

- teach from directly, or project during class
- check a student's approach against a reference implementation
- sanity-check the auto-checks themselves still pass after any edits to
  `generate_data.py` or the notebooks

Every exercise in every solutions file has been verified to actually
trigger its own "Correct!" callout — not just "runs without crashing."

## If you change something

- **Edit a lab's markdown/demo content:** mirror the same edit in the
  matching `solutions/` file so the two don't drift apart.
- **Edit an exercise's expected answer or check logic:** update it in both
  the lab (the check cell) and the solution (the worked answer), then
  re-open the solution notebook and confirm it still shows "Correct!".
- **Regenerate `data/`:** re-verify both the lab checks and solutions still
  pass — some checks depend on exact counts (e.g. "exactly one duplicate
  athlete", "5 goalkeepers") that assume the current generator output.
- Run `marimo check path/to/notebook.py` after any manual edit to a
  notebook file — it catches structural issues (e.g. a cell reading a
  variable no other cell defines) before you open it in the browser.
